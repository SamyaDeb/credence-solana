# Phase 1 audit (Oct 8–12, 2026)

Internal audit of `programs/credence-core`, `keeper/` and `app/` before the Phase 1 submission. Each finding has a
failing test written first, then the fix. A finding that is not fixed has its reason here and is listed in the
README's Known limits.

Severity: **critical** (funds lost or stuck with no exit), **high** (vault overpays or a user loses funds under a
plausible action), **medium** (wrong result or blocked flow under an unusual condition), **low** (hardening, no loss
path found), **info** (documented behaviour).

## Summary

- **Scope:** every instruction of `programs/credence-core` (account validation, signers, PDAs, mints and token programs,
  `paused`, look-alike accounts), the oracle and settlement windows, the vault (inflation, rounding, queues, insolvency),
  the admin bounds, the keeper's failure paths, and the app's server routes, redaction and build output.
- **Method:** attack first, as a failing test (LiteSVM for the program, vitest for the keeper and app, Playwright for
  the UI), then the fix, the test passing, one commit per finding.

  a `/code-review` pass and a `/security-review` pass over `485c088..HEAD`. The code review's findings were verified
  and became A-14 to A-20; the security review reported no high-confidence vulnerability.

  `MAINNET_RPC` and Pyth key values: 0 hits); surfpool and the app listen on 127.0.0.1; `.env`, keypairs, ledgers and
